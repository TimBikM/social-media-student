Best practices for structuring a large React application?

Posted 2 hours ago 1.2k Views 24 Replies
AlexDev
Senior Member
4.2k

Hi everyone,

I'm about to start a new enterprise-level project using React. In the past, my projects have gotten quite messy as they scaled up. Files were everywhere, state management became a nightmare, and finding components took too long.

What are your go-to architectural patterns for large React apps in 2024? Specifically looking for advice on:

  • Folder structures (Feature-based vs Type-based)
  • Where to put global vs local state (Redux/Zustand vs Context)
  • Handling API calls (React Query?)

Any boilerplate repositories or articles would be greatly appreciated. Thanks in advance!

42

I highly recommend a feature-based structure (sometimes called "screaming architecture"). Instead of organizing by components/, hooks/, and services/, organize by domains like features/auth/, features/dashboard/.

Inside each feature folder, you keep the components, hooks, and API calls specific to that feature. It makes deleting or refactoring features infinitely easier down the line.

For API calls, React Query (TanStack Query) is an absolute must in 2024. It handles caching, loading states, and background fetching out of the box.
